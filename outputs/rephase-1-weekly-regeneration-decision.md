## Architecture findings and decisions

1. **Old evidence rejection differs from impossibility of producing new evidence.** Receipt replay rejects changed control bytes against its generating commit. Historical checkpoint validation instead compares its report to its recorded contract/implementation; a new committed helper does not intrinsically invalidate State. New receipt construction uses actual current HEAD. These distinctions make a narrow refresh worth a real witness before adding runtime APIs.
2. **The pending role map covers checkpoint rows, not every transitive file.** Absent authored input/receipt/reader-input paths are neither authorized nor rejected by that map merely by being absent. Their content is checked by receipt replay, accepted derivation and persisted review. Do not infer a new Human approval requirement for every authored-input edit. This does not authorize upstream mutation or content refresh in the selected witness.
3. **No standalone prepare/classification CLI is selected.** It would add an interface without demonstrating successful regeneration. No staged-render/transaction framework is selected either; existing validators require canonical paths, so a temporary directory is not automatically a valid alternate repository/authority context.
4. **Select only byte-identical mechanical refresh for the next experiment.** After a committed nonsemantic control change, accepted/authored inputs, complete reader input, main/bib/style, PDF, manuscript, all substantive reviews/QA and their criteria must be unchanged. The experiment may construct a new receipt under current tools, renew the Gate, and establish the existing revalidation record/pointer. This is not publisher rerun, changed-output regeneration or blanket review reuse.
5. **Review reuse is conditional on targets and criteria, not only visible prose.** For the witness use harmless Python comments in the existing Weekly helper; assert unchanged review config/schema/check families and semantic implementation (comment-only change). Keep review/PDF/manuscript bytes identical. This isolates mechanical identity change; it does not prove that arbitrary Core changes preserve reviewer criteria or semantic meaning.
6. **Build-transfer gaps remain separate.** Current Weekly stage PDF is `survey_root/main.pdf`. The older semantic-quality helper's next-action literal and alternate preview path are compatibility divergences, not a competing current canonical authority. The build workflow uploads PDF+digest, checks but does not upload the log; the six-name directory policy is an allow-list, not a requirement that all six files exist. Result reference hashes do not prove preflight execution/source→PDF derivation. No new build is necessary for the selected unchanged-output experiment; changed-output regeneration still needs that real operational witness.
