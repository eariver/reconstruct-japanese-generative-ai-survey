## 1. Decision and alternatives

Select a **typed versioned renewal operation with a reloadable current source-proof leaf**, a bounded R3-to-renewal compatibility adapter, and the existing single State selection pointer. Both generated routes (Weekly envelope / THEMATIC LONGFORM_SPECIAL) and both cases below are required in the implementation unit:

* **U — exact-target reuse:** same complete reader, current rederivation produces exactly the existing source trio; old manuscript/source/PDF/build evidence and review records stay at their original paths. New current mechanical evidence, QA, Gate, Candidate and seal; no rebuild claim.
* **C — new rendered targets:** same complete reader, but new source/manuscript/PDF target identities. Real build and new external postrender semantic/visual reviews at exact new targets. Same SHA at a different target path is still C.

The initial Worker A/B plans are **NO-GO as submitted**. Existing P1/P2V/P3S, old seal layout, and old proposal's before-State do not implement this operation. Their later corrections are inputs, not independent approval; contradictions are resolved in the root resolution. Reject reason-only admission, unmodified consumers, caller-verified dictionaries, global pending overrides, rewriting old review targets, and running old R1 on versioned State. Also reject a U scope restricted to unchanged P3S tool bytes: it would avoid the actual Core-renewal problem.

A new immutable root is permitted without inventing an editorial change. It is a **renewal basis**, not a P1 correction proposal. No changed-reader waiver is added to P1. The selected design costs a typed compatibility/proof path and consumer integration; it avoids old-code execution, canonical overwrite and redundant U reviews. Cost savings remain unmeasured.

## 2. Eligibility and supported transition

Entry is canonical current State at `VALIDATED_DRAFT`, Architecture approved, Preview pending, no decided Preview/Freeze/Release and no active Exception. State selects a complete existing versioned editorial or renewal set. Canonical initial publication renewal remains the existing separate R1 scope. Missing/foreign/ambiguous authority refuses. The old set may be **ineligible under new current tools**; it must nevertheless pass the selected historical structural/evidence validator. Do not require the failing old full current receipt as an entry predicate, nor describe the old active pointer as healthy current acceptance after a Core change.

Two transitions are explicit:

1. **Bootstrap:** known R3 shapes and source closures from the actual57 lineage → implementation containing this renewal contract. The implementation adds the strict branches below, explicitly registers its new schema/module closure and preserves the legacy shapes. This is a bounded compatibility adapter selected here, not an assertion that all old and new tool/schema bytes are equal.
2. **Steady state:** renewal-capable source → later committed implementation change under the same renewal contract and supported shapes. The runtime derives actual old/new tool commits and changed paths; prose alone is insufficient. Artifact-only commits do not qualify as a new Core renewal. Recognized same-contract style/rendering implementation changes are allowed and classified by actual source/target identity. Changes to research acceptance, Profile, Architecture, Draft authority, pipeline/quality semantic contract, review requirements, route family or build recipe specification refuse and require a separate selected migration. Executable tool versions may change for C under the same fixed recipe/specification; U retains the historical build unit.

Bootstrap has an explicit finite old-format adapter; steady state requires exact current closure membership and schema/contract equality, apart from permitted implementation/style bytes. No wildcard `scripts/**` historical exemption and no caller-supplied compatibility allowlist. Before implementation, return the exact old-format fingerprints and old/new closure map derived from the saved57 manifest and proposed code graph. This mechanical binding is part of the pre-code return, not authority to broaden the accepted formats.

Dirty/untracked current control roots, unavailable historical tool commits/blobs, nonancestor tool epochs, unsafe paths, changed research or Profile, and unrecognized old shapes refuse before operation writes. Check actual historical membership; never restore missing objects from network or forge ancestry. Old P3S `producer_head` and receipt `current_tools.repository_commit_sha` are separate epoch fields and must agree where their dependency rows overlap; a field is not silently replaced by HEAD.

## 3. Historical evidence, tools and current derivation

Introduce a finite **historical identity evaluator**, below the active resolver. It does not run old code, call old full current validators, establish genuine approval, or return reusable permission tokens.

| Domain | Historical identity check | Current eligibility check |
|---|---|---|
| Immutable evidence E: proposal, accepted research, reader, staged outputs, receipt, reviews, Candidate, seal, records | Reload exact repo-contained paths and hashes/sizes; strict recognized shape, self-digests, typed cross-bindings and provenance chain | Same retained inputs must remain exact; new current derivation and current validation of applicable content predicates |
| Mutable State copies | Resolve the recorded COPY mapping, original source ref and retained bytes; State→Profile relation; exact retained inventory | Fresh canonical current State and independently derived current selected predecessor; never require live State to equal an earlier proposal's before hash |
| Repo tool T: receipt closure, P3S code deps, registered schema/style/recipe refs | Each typed row checked against its own recorded tool epoch's Git blob (and mode where represented); no requirement that old tool bytes still occupy the live path | Committed current closure equals live and loaded source, clean roots, expected membership, current contract and tool checks |
| External executables/build environment | Recorded original build/tool evidence, not a Git blob or re-probe of an absent executable | C probes/uses the selected actual executable and fixed recipe; U makes no new build/environment claim |

**Evidence is not required to exist in the tool commit.** Publication records are normally produced after that commit. Conversely, recorded historical tool hashes cannot be accepted merely because a receipt lists them. Historical schemas are supported by the finite compatibility evaluator and cross-checked against the corresponding epoch; arbitrary historical schema code or remote `$ref` is not executed/fetched.

Important actual-source detail: P1 `_before_graph` adds `receipt:tool-closure:*` nodes (`survey_editorial_correction_proposal_v2.py:955–958`), normally KEEP under `_pol` (`783–791`). Therefore old P2R KEEP is **not all publication evidence**. The historian classifies tool rows from their typed receipt edges and fixed closure membership, not merely `KEEP` or a directory prefix. Evidence KEEP still requires live original bytes. A row used as both evidence and tool must satisfy both; unknown/ambiguous roles refuse. Existing standalone P2R/P3S validators retain their current semantics; the new historical evaluator does not silently change their PASS meaning.

History outputs must say `HISTORICAL_IDENTITY_VERIFIED`, not current-ready or replayed. Present-current renewal source verification separately rederives the entire canonical reader and source trio from the same accepted research and authoring. No old execution/reproducibility claim follows from blob equality.

2. `survey_versioned_renewal_source_v2.py`: detached basis/source-proof validation, accepted-authority assembly and current projection/render comparison. Function-local imports where needed; no current State validation, seal resolution, P1/P2V/P3S/full receipt or Reader/Gate/Candidate calls. 3. `survey_versioned_renewal_v2.py`: current invocation authority, exclusive capture/prepare, build transfer, finalize, activation/resume and CLI. Old prior set references are not a cycle to the new set.

Historical accepted State-SHA evolution is allowed only through the already content-addressed accepted-package rule, not arbitrary new State or changed package acceptance. The new operation separately checks current nonpublication State/checkpoints equal those inputs. No monkeypatch, caller `already_verified` records, arbitrary implementation-SHA substitution, or broad `pending` allowance.

Reuse pure `weekly.build_reader_input/validate_reader_input/render_main/render_bibliography/validate_generated_closure` and Longform projection/archive-authorization/canonical-bytes/render helpers after that loader. Preserve token safety, accepted Draft restrictions, DID/card/primary/access mappings, directive refusal and full accepted-ref equality. Content equality is the complete canonical reader bytes at the existing reviewed path, not headline/prose equality. If any accepted-research predicate cannot be made State-free without weakening it, return the exact blocker before coding; do not replace it with hash-only acceptance.

The detached proof is valid for readback after activation: it validates its **retained before-State**, not a requirement that live State still be the before-State. Only high prepare/finalize/activate/resume compare live current-before. Active normal consumers independently validate current State and the selected new set. This separates authority timing without a public skip flag.

## 5. Namespace, schemas and output identities

Let `P` be the original editorial proposal namespace, kept unchanged. Let `R=P/renewals/<renewal_id>`, where `renewal_id` is a nonempty single lowercase ASCII segment matching `[a-z0-9][a-z0-9-]{0,63}`. Repeated renewal remains under the same P with a distinct id; no recursive `renewals/.../renewals` and no latest-directory selection.

Four new strict schemas:

* `versioned-renewal-basis-v2.schema.json`: `VERSIONED_RENEWAL_BASIS_V1`. issue/Profile/route/original proposal refs; exact before-State source ref and retained-copy ref; prior selected record/set/Candidate; original validation/canonical anchor; unchanged authoring/reader/accepted refs; old/current tool epochs; closed typed retention rows; requested `REUSE_TARGETS` or `RENDER_TARGETS`; executor/time; `basis_sha256`.
* `versioned-renewal-source-proof-v2.schema.json`: `VERSIONED_RENEWAL_SOURCE_PROOF_V1`. basis ref; existing exact reader/authoring refs; full accepted refs; supported contract/epoch refs; current dependency closure; sized output trio refs; current reader/render comparison digests; optional **U-only** old manuscript/build-unit refs; `proof_sha256`. Derived disposition `REUSED_TARGETS` or `NEW_TARGETS` is validated, never accepted as caller permission.
* `versioned-renewal-source-manifest-v2.schema.json`: `VERSIONED_RENEWAL_SOURCE_V1`. basis/proof refs, route/issue/Profile, reviewed-reader/authoring/accepted refs, current tools, sized output trio, build record ref, and `receipt_sha256`. Build record has exactly one tagged variant: historical `REUSED_BUILD` with original record/PDF/log/digest refs, or `EXECUTED_BUILD` with actual input/output/tool/exit evidence under the selected existing recipe.
* `versioned-renewal-publication-set-v2.schema.json`: `VERSIONED_RENEWAL_SET_V1`, `SEALED_INERT`, basis/proof/receipt/build refs, same exact 15 role names, `set_sha256`. This is a new set kind, not a relaxation of old fixed `<P>/publication` paths. The low validator explicitly cross-binds proof/basis/receipt refs in addition to role maps.

All objects have exact keys, strict duplicate-key rejection, normalized repo-local no-follow refs, lowercase SHA, strict instants/sizes and cross-field agreement. The pre-code return must supply full field/type/required/conditional definitions implementing these lists; inventing an extra authority field requires root review.

Owned files in R: `renewal-basis.json` (written after owned COPY/inventory), `retained/before/<original-State-relative-path>`, `renewal-source-proof.json`, `validated-source-manifest.json`, `build-record.json`, `quality-regression-bundle-v2.json`, `reader-surface-gate-v2.json`, `publication-candidate-v2.json`, `publication-set.json`; C additionally `staged-source/{main.tex,references.bib,jgaisurvey.sty}`, `build/{main.pdf,main.log,main.pdf.sha256}`, `reader-manuscript-v2.json`. The new source proof is C's staged proof; do not forge an old P3S manifest at an unsupported renewal path. U writes no duplicate reader/trio/manuscript/PDF/log/reviews. Build auxiliaries stay disposable. Supplied QA/review records can be external safe repo paths; they are pinned, not writer-owned. Actual exclusive inventory includes explicitly declared evidence files inside R, not arbitrary untracked files.

Snapshot capture is two-phase: compute/pin/refuse in memory, claim exclusive R and write COPY, then basis last and recheck all entry pins. Incomplete R remains inert; retry uses a new id. No same-byte takeover or cleanup of foreign/unknown residue. Existing P2R retained roots and original P3S closed4 are unchanged.

## 6. U/C, proof context and review obligations

`REUSE_TARGETS` is a request to attempt U, not a proof. Current renderer/style must yield exactly the old trio and complete reader; old manuscript must satisfy all current source/Architecture/fidelity requirements. Keep original target paths and exact old manuscript/source/PDF/page count, build record/log/digest and review records. The current fixed review/check contract must still accept the original scope of those reviews; no inference of genuine approval. New QA inputs come from fresh actual checks with exact evidence refs. `quality.validate_checks` validates supplied results; it does not execute those checks. New wrapper evidence does not invent a new TeX build.

On reuse mismatch refuse with a named reason; do not auto-switch an already claimed root into C. A separate `RENDER_TARGETS` attempt makes new targets and needs real build plus new postrender semantic/visual review. This is C even if the build yields the same PDF SHA at a new path. Source-only/comment-only changes, PDF metadata-only changes, or different manuscript paths do not carry old exact-target reviews. Early same-reader review may remain historical input, subject to exact target and unchanged scope-contract checks; it does not approve the Core change or substitute for C reviews. Original P2V `SCOPE_BOUND` on an already activated proposal is not re-invoked.

U's old manuscript embeds old `editorial_source`, so a new receipt alone cannot make its standalone validator current-valid. Add **explicit reloadable proof-ref context** to Reader manuscript/review loaders. With a valid matching U proof they check old source-proof identity historically, then all current manuscript semantics and exact trio against the new proof. Without that context, old standalone editorial validation keeps its existing current P3S requirement and refusal. C manuscripts instead contain a new mutually exclusive `renewal_source` ref to the source proof. Never edit an old manuscript or review record to add context.

New Candidate and QA bundle carry `renewal_source_proof_ref` in their strict optional renewal branch **and digest base**. New Gate derivation carries proof and receipt refs and no longer infers the old `<P>/publication` receipt path. Review record schema/bytes need not change: validators receive a reloaded exact proof ref from their containing Candidate/prepare invocation. Wrong issue, manuscript, source, PDF, proof path/hash or basis refuses. Full set validation demands Candidate/QA/Gate/receipt/seal agree on the **same** proof; equal-SHA different proof paths are not silently substituted.

Preseal calls may provide explicit untrusted proof refs and must reload them. Normal active consumers derive proof from the State-selected set and demand equality with Candidate/QA/Gate bindings. A self-validating inert Candidate is not live selection. No ambient/global context or cached authority. The low resolver hashes and cross-binds only; it must not call full Reader/Gate/source proof semantics and recurse into State.

### 11.2 Proof threading and current U predicates

Keyword name on Reader manuscript/review builders and validators: `renewal_source_proof_ref=None` (exact `{path,sha256}`, reloaded). ### 11.3 Accepted-authority gate, supply boundary and remaining deliverables

[Accepted-authority predicate map](../notes/rephase-1-versioned-renewal-contract/accepted-authority-predicate-map.md) is an author-side source inventory, not a completed extraction. Required leaf entry is `load_renewal_accepted_authority(root,basis_path)`; no State object, implementation-SHA or verified-records parameter. Source proof calls it by persisted path. Families F1–F8 cover Weekly/Longform accepted rows/archive/projection, Evidence package/tasks/cards/supplements/acceptance, Screening package/tasks/results/coverage, narrow accepted State-SHA rule, draft/token/directive checks, graph typing and retention mapping.

The map honestly leaves Ledger/Discovery/X/Materiality/completeness State-free verification open. The pre-code return must trace P1's full pipeline validation as well as the two route loaders and explicitly cover these families, Selection/Synthesis/Architecture/Draft checkpoint acceptance, research raw/access/card lineage and all relevant transitive predicates. **Do not treat route loaders' lack of dedicated validation as authority to omit a family.** Exact paths/digests alone are not sufficiency. The existing narrow package State-SHA exception requires exact accepted package hash, canonical source State path, same issue/Profile, and the valid retained before-State/COPY chain; all other package/prompt/schema/task/acceptance predicates remain. It does not require original acceptance-stage State bytes that were never retained, and it does not allow arbitrary package/State substitution. Old acceptance provenance is checked as history; current content predicates run on that exact accepted graph; high invocation checks current nonpublication selection still agrees.

Supply boundary: externally produced QA/review files are read-only inputs. Finalize first reloads schemas/results/targets and computes an exact dependency manifest (path/hash/size/type) including any files inside R; excludes unlisted files, pins directory inventories, rechecks before/after writes. Preparation must not claim an already-existing foreign R, and writer-owned paths cannot alias supplied paths. External files are never deleted/rewritten. Pre-code must specify which QA evidence fields prove the actual fresh check results; no invented execution metadata or numeric savings.

Remaining pre-code deliverables are therefore substantive: complete predicate/call inventory with State-free replacements; exact branch schemas/digest bases/keyword propagation; concrete old-format fingerprints from actual57; full successor closure lists and controlled bootstrap additions; current control diff path classification and recipe-specification boundary; historical Git tree modes vs physical permissions (no symlink or unselected mode migration); source/fixture/CLI/write/seam map. Until Astra confirms these, **implementation is blocked**. If a predicate cannot be preserved, revise the contract or record precise NO-GO. This design review does not waive that gate or certify constructibility by itself.
