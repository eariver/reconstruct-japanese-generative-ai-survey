## 1. Decision

Select **one generated Thematic Longform reader-input/derivation direction**, rather than implementing an opaque declared-source bundle and then a second adapter. The next bounded increment is **LF-1: schema + source-only reader-input projection/accepted-source feasibility**, with an internal source/fixture review before implementation. Physical source materialization, receipt/Gate integration and publication acceptance follow only after that evidence; they are not certified by this decision.

Preserve **DIRECT_PRIMARY / PRIMARY_ONLY** exactly as a limited capability. Its existing manifest/support hashes and later reviews remain useful; it is not silently upgraded to complete supporting-surface semantics. No migration/revalidation of historical editions, no universal TeX parser, no new reviewer role, and no reuse of later Publication Review PASS as pre-TeX authority.

Initial generated scope is **THEMATIC + LONGFORM_SPECIAL**, first-generation preparation at configured `DRAFT_COMPLETE`. The first authored format is explicitly **four-family lineage v1** (the existing `glm/qwen/deepseek/kimi` comparison shape), not all Thematic topics. Retrospective generation and arbitrary/manual multi-file TeX remain unproved. Their existing primary-only capability stays; other document shapes need their own explicit mapping rather than masquerading as this format. `LONGFORM_INITIAL` in the Worker note is an operation shorthand, **not a new publication-profile enum**.

## 3. Why not the proposed raw declared-source bundle first?

Current Gate derivation accepts DIRECT_PRIMARY or the supported Weekly generated route only. A Special bundle would already require a new target, route/schema, producer and readback: it is not a schema-free manifest tweak.

More importantly, “all declared input bytes invalidate review” and “nonreader comment/layout changes do not” cannot both be promised without a defined projection. An opaque TeX collection does not yield exact emitted reader values by hashing it. A declaration list or lexical blacklist does not establish all TeX dependencies; `\def`, `\csname`, catcodes, Lua and computed reads make an unspecified “renderer construct set” inadequate. The Worker correction still proposed a projection without defining that inverse parser; **that claim is not selected**.

A conservative exact-source-set review could honestly bind declared bytes, with extra re-review costs and no complete build-closure claim. It does not deliver the desired semantic/mechanical split, and building it before a generated adapter would add migration/duplicate interfaces. The generated direction instead uses finite trusted serialization from structured reviewed content. Its schema/authority/replay work is substantial and **not estimated as zero or automatically cheaper**; it is justified by the selected sufficiency/provenance/invalidation goals. Net lifecycle savings remain unknown. Do not invent a parser/framework to rescue a smaller-looking diff.

This is a logical reader-content/structure model, not a prediction of every rendered glyph/page number. No renderer may reread unreviewed prose from raw upstream dictionaries after review.

## 5. Accepted-source mapping — first eligible subset, no invented authority

Resolve accepted Profile/Architecture/approval, Draft Package/Result/Synthesis, Evidence, Candidate Matrix, Materiality and Discovery via current validated State/checkpoint references and existing validators. Do not substitute canonical path presence for acceptance. Publication-authored cover/revision/summary are **authoring choices constrained by accepted sources**, not automatically checkpoint-accepted research or text copied verbatim from Draft.

- Validate acceptance and each named card path/hash through the existing Evidence API. B's `_strict_evidence_sources` is a useful pattern, not automatic Longform support. B's `_records_from_authorities` is **not** a drop-in projection: it deliberately uses Matrix title, `Unknown`, and Discovery `source_locator`; Longform currently intends entity metadata.
- **Initial eligible subset:** a cited DID resolves exactly once inside authorized Draft Package evidence inputs and to one accepted card; require a single DID in that card's acceptance row for the first mapping proof. Multi-DID/card attribution or other ambiguous mappings stop, not a heuristic flattening. This limitation must be visible, not advertised as generic Thematic completeness.
- Select the unique accepted entity whose `entity_id == card.artifact.primary_subject_id` (card schema exposes that existing authority; Evidence validator requires a registered entity). Use its nonempty `canonical_name` and non-null/nonempty `canonical_url`; organization comes from that same entity, with explicit literal **`Unknown`** for null/empty organization, preserving the intended fallback rather than guessing another entity/host. Multiple entities are not automatically ambiguous if the primary-subject match is unique. Missing/ambiguous required fields stop.
- Resolve access provenance **only from that validated card's sources** matching the selected URL, using existing `resolve_source_access_provenance`. Equal-timestamp duplicate captures follow that function's current rule; different-timestamp ambiguity stops unless a future explicitly accepted selection contract is defined. No unbound sidecar `sources`/`source_bindings`, min/max/latest/date-of-window fallback. Technical-note URL must match the selected accepted canonical URL; a conflict with old authoring data is an explicit refusal, not a silent rewrite.
- Check Matrix/acceptance/Card status and Materiality/Discovery bindings. Only supported factual sources (VERIFIED/PARTIAL with existing downstream eligibility, never HOLD/NEEDS_MORE/REJECTED promotion) enter this first route. URL membership/class labels do not prove every claim's truth or first-party status: source-role/strength/date fidelity still requires existing substantive review (DM-020/013).
- Derive package authorization from validated accepted Draft Package `evidence_inputs`/candidate rows. The current base passes `_assigned_ids(spec)` from authored archive into `validate_revision`; that is **not itself Architecture acceptance**. Reuse exact-one `survey_drafting_citation_refs_v2.refs` semantics to check archive→accepted Draft Result refs for Draft-derived deck/blocks. Revision-authored placements may differ from raw Draft, but remain within authorized package source choices and are explicitly captured in the reviewed object. Do not demand equality with unrendered Draft prose or infer support from a public key merely existing.
- Preserve approved Architecture/final-synthesis and applicable Human directive reading obligations. The legacy adjacent post-Architecture directive file is not made accepted Human authority by a path/hash or `review_reference` string. LF-1 must identify its existing authority/control role; unresolved conflict or missing authority stops before publisher integration, not by dropping a substantive requirement or inventing a new gate.

DM-016/017 remain separate upstream source-class/obligation prerequisites. An actually invalid/unconstructible accepted fixture is a concrete stop; the mere existence of those deferred IDs is not an automatic demand to repair them in LF-1. Shared extraction of helpers is permitted only after concrete profile-neutral caller/closure analysis; do not silently move Weekly helpers/change its CURRENT_CLOSURE or import Weekly closing-summary policy.

## 6. Generated closure, operation order and implementation boundaries

The full prospective increment (after LF-1 feasibility) must provide:

1. Initial producer at configured DRAFT_COMPLETE/`stage:reader-publication-validation`: validate authority/input, materialize **reader input only**, then require a real persisted independent Reader-Surface PASS for those exact bytes before TeX/Bib/style writes. No synthetic PASS from longform preflight/review-reference text.
2. Same-object rendering to only canonical `main.tex`, `references.bib`, copied trusted `jgaisurvey.sty`; safe escaping/URL/token handling, no raw-TeX escape hatch. Exact local input inventory; optional declared output files main.pdf/main.log/main.pdf.sha256 are not all mandatory. Extra local inputs/auxiliaries/symlinks, dynamic/arbitrary includes, alternate style or unsupported format stop. No arbitrary included reader blocks in this first scope; no fidelity parser rewrite selected.
3. One strict mechanical source receipt (new narrow Longform schema; existing filename may be retained with explicit route/schema rejection of legacy shape), exact authoring/accepted refs, code/helper/style/schema/control closure, exact outputs and review binding. Independently rederive the reviewed input and all outputs; refreshed hashes alone are not proof. The generating State hash is historical provenance, not an equality requirement on the later advanced State.
4. Explicit Gate derivation route/scope and matching target/Profile; existing expected-manuscript admission remains. Readback works at applicable later lifecycle stages with validated current accepted authority; write entry restrictions are not blindly imposed on readback. Existing DIRECT_PRIMARY remains visibly PRIMARY_ONLY and cannot count as this new generated acceptance or a fallback on malformed Longform input.
5. No Special use of the Weekly R1 owner by default. Pending Preview/post-validation regeneration is separately unsupported until its ownership/retention/failure contract is proved. Any new-operation invocation at an unsupported lifecycle must refuse **before** the old wrapper could delete files. Legacy deletion behavior is not a certified path to reuse or a second writer to duplicate.

Actual full-increment path budget is provisional, not a two-file promise: new `scripts/survey_longform_derivation_v2.py`, reader-input and Longform receipt schemas; existing public/base Longform entrypoints and active wrapper serializer; Gate/runtime/schema and reader wrapper as actual forwarding requires; contract registration and focused tests. `survey_reader_fidelity_v2.py` and manuscript schema stay unchanged unless a demonstrated necessary interface gap is separately selected. Thematic hardcodes are retained as explicit format restrictions initially, not silently generalized by renaming headers. Every expansion has to earn its lifecycle cost.
