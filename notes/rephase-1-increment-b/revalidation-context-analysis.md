# Increment B: pending publication revalidation context (read-only analysis)

2026-09-24. Analysis of the isolated Ubuntu B development tree at `daa1dd3b0f1294a83bea1738d9bdfb3dcac80712` plus uncommitted helper/tests. This is a design recommendation, not implementation, a test result, an independent audit, or production adoption.

## Finding

The real generated Weekly route can deadlock during legitimate `VALIDATED_DRAFT` publication revalidation. The canonical `survey_root/main.tex` and other publication files have to hold the new bytes before Gate/QA can validate them. The still-active validation checkpoint binds their old bytes. `revalidate_publication_surface` recognizes exactly changed publication rows and verifies all preserved/upstream rows (`scripts/survey_agent_control_v2.py:1343-1375`, `:1221-1277`), but its Gate call (`:1422`) enters `surface_gate.validate_reader_surface_gate` -> `_derivation_for_manuscript` -> `weekly.validate_receipt` -> `load_derivation` (`scripts/survey_reader_surface_gate_v2.py:1660`, `:1094`; `scripts/survey_weekly_derivation_v2.py:601-631`, `:418`). `load_derivation` calls whole-State `agent.validate_agent_state` and each `resolve_checkpoint_artifact` calls it again (`scripts/survey_agent_control_v2.py:322`, `:459-484`). Whole-State validation rejects the old validation-checkpoint hashes until a revalidation record is active. Also `_strict_evidence_sources` calls `evidence.validate_evidence_acceptance` inside `current_stage_basis_override` (`scripts/survey_weekly_derivation_v2.py:126-131`); that wrapper reaches whole-State validation through `verify_current_stage_basis` (`scripts/survey_agent_tool_v2.py:42-51`, `:122-137`). Thus fixing only the first call is insufficient. An alternate output location cannot satisfy the exact canonical primary path.

## Recommendation: a verified, ephemeral *pending* basis

Build one narrow prospective basis from the actual current State, its exact validation checkpoint and the on-disk current publication bytes. It is a verification context, never a State pointer, revalidation record, Human Gate, or approval. Construct it only when State is `VALIDATED_DRAFT`, Architecture Review is approved with intact provenance, Publication Preview/Freeze/Release are pending, Exception Gate inactive, and the State-bound prior validation checkpoint is schema-valid and exact. Compare every row of that checkpoint with current disk; allow changed rows only for the existing bounded publication roles and canonical publication/survey paths, with unique `(name,path)` identities, old SHA from the checkpoint and new SHA/byte count from disk. Require at least one changed row. Verify every other checkpoint record, upstream artifact, deterministic result, Profile, history/control field, and any existing revalidation chain; a malformed or unrelated State error is fatal. The existing `_verify_preserved_provenance` and `_validate_checkpoint_record(..., revalidation=...)` contain the needed byte-check logic but currently accept a record-shaped active context and do not themselves validate the complete pending State. Refactor shared private validation to accept only an internally constructed, fully checked prospective basis; keep the public `validate_agent_state` and ordinary `resolve_checkpoint_artifact` strict. Never write or synthesize a revalidation authority to make those validators pass.

Pass this verified basis to the Weekly loader as an explicit narrow object, not a caller Boolean. The loader should resolve only named accepted upstream checkpoints through the basis and retain the existing exact checkpoint/schema/unique-artifact checks; do not let publication rows become upstream authority. Its Evidence acceptance validation also needs a narrow pending-aware current-stage basis wrapper: current HEAD must still match, and the existing content-addressed historical Screening/Evidence State-SHA accommodation must remain the only historical exception. A failed acceptance/package/card check remains fatal. This likely requires `scripts/survey_agent_tool_v2.py` as a **thirteenth runtime path** to expose a checked pending-stage verifier (or an equivalently narrow existing-wrapper refactor); the approved twelve-path inventory alone does not cover that whole-State callback. Do not monkeypatch a global validator to ignore arbitrary State errors or substitute initialization SHA.

Gate creation and Gate readback should choose the same context from actual State: normal strict State when `DRAFT_COMPLETE` or when a real State-bound active revalidation record validates; prospective context only for the recognized pending `VALIDATED_DRAFT` transition. A malformed active pointer must fail closed; it cannot be silently treated as pending. `revalidate_publication_surface` should construct/verify the prospective basis before Gate replay and require its exact superseded/preserved row set to equal the rows later written to the real record. The later-stage reader remains on strict active-record resolution after the record and State pointer exist. Only successful Gate replay, complete QA and existing lifecycle checks may write the actual record/pointer, followed by ordinary strict State validation. Failure must leave both absent/unchanged. The current code writes record/State before post-validation (`scripts/survey_agent_control_v2.py:1501-1510`), so this post-write failure path needs transactional treatment or preflight sufficient to prevent a half-written authority.

This is bounded scope growth in implementation interfaces, not a new authority. If exact prospective State validation and the Evidence wrapper cannot be shared without broad weakening or historical State reconstruction, stop B and return that finding to Astra. A positive regenerated-Weekly revalidation plus upstream-tamper, wrong publication role/path, stale/malformed pointer, changed Evidence package/card, and no-write failure witnesses are required before claiming the solution works. No such run was performed for this analysis.

## Addendum: a prior State-bound revalidation pointer

The resolver currently interleaves immutable-record checks and live publication checks (`scripts/survey_agent_control_v2.py:762-903`). Its `_load_revalidation_record` already authenticates the State pointer's exact file hash and schema (`:639-663`), and `_check_revalidation_chain` authenticates linked record files (`:665-696`). The intervening checks compare record identity, establishment, exact prior validation-checkpoint reference and record rows against that checkpoint. Checks of superseded/preserved artifact files, validation manuscript/bundle/reviews/PDF, and post-decision Human/PDF agreement are *live* checks. They will fail legitimately after pending regeneration. A current Core tool change is not itself a structural pointer defect; current-tool matching belongs to the prospective replay and final new record, while the old record retains its historical tool identity.

For a repeated generated Weekly revalidation, split that resolver's **immutable prior-record verifier** from its live-active verifier, preserving the latter's public behavior. The immutable verifier must reject malformed/missing/hash-drifted State pointer and chain, issue/reason/establishment mismatch, wrong or drifted State-bound prior checkpoint, duplicate/unknown/missing prior artifact identities, wrong old/new SHA relationship, publication-role/path escape, malformed validation references, and broken supersession links. It should compare the union of record's superseded and preserved `(name,path)` rows with the exact prior checkpoint row set, and each stored old/preserved hash with the checkpoint; no current publication file is used as proof that the old record remains active. The prospective verifier then uses **current** bytes and the canonical State/checkpoint chain to build a fresh exact pending row set and replay new Gate/QA. A valid immutable record is historical provenance only while pending; the old pointer is never reclassified as a valid *active* record. A newly written record may `supersedes` that exact verified pointer only after full success. If an existing Human decision is present, stop instead of allowing pending replay to bypass its PDF agreement.

Three cases are distinct: (1) no pointer: validate the prior checkpoint and pending rows directly; (2) pointer whose full live resolver passes: use strict active authority for ordinary readback, and permit a new pending context only if actual bounded publication bytes subsequently differ; (3) pointer whose immutable checks pass but permitted publication files have changed: it may be a stale legitimate predecessor for another pending revalidation, subject to the fresh prospective checks. Any other resolver failure must remain fatal. Do **not** classify staleness by catching an error string from `resolve_active_publication_revalidation`; the structural/live split must be explicit and the pointer cannot fall back to `None`.

There is a smaller B boundary if repeat support is not essential now: support **first** generated Weekly revalidation only when the State pointer is `null`; fail closed with an explicit “generated Weekly repeat revalidation unsupported” result for every non-null pointer while leaving existing direct-primary repeat behavior intact. That is reasonable as a disclosed support limit because it avoids a partial structural/live split; it is not evidence that repeated revalidation works. It must be an Astra scope decision and a tested negative, since the existing `revalidate_publication_surface` otherwise advertises repeat support (`:1450-1470`).
