Contract§4 explicitly requires strict duplicate-key refusal for new authority, and §§7/9 require observed failures/primary-secondary classification. Hash binding does not excuse a malformed record first presented with a matching fresh hash. Do not weaken these requirements by declaring the risk negligible.

Selected corrections, no new business feature:

Reuse a shared strict parser if appropriate; do not cache parsed authority or validation success. Existing valid legacy JSON remains valid. 2. Every observed close error in new high-level read/write boundaries and shared activation record/State writer must be surfaced/classified. Preserve the earlier primary exception and attach secondary close/readback errors; no `except: pass`, no “close success” inferred from fsync. Preserve partial/foreign/possibly referenced files and old/new/unknown State observations. This does not promise power-loss atomicity.

Historical inspection has its explicit separate API. This clarifies the existing strict-current-State requirement; it does not add an approval role/token or require the proposed set already be active.

Handle the declared supported source roots or explicit State selection; no broad recursive glob followed by treating every snapshot as live. Invalid State/pointer is never canonical fallback.
