No `main`, all-history clone or archive acquisition. 3. **No explicit `git config` updates.** Use supported init/remote/fetch/sparse-checkout commands. Filtered fetch may configure its own promisor metadata; inspect actual behavior. Do not issue preflight's explicit `git config remote.*` commands. Acquisition is a read-only, fixed-commit phase; after materialization remove acquisition remote and add only inert origin. Subsequent operations use `GIT_NO_LAZY_FETCH=1`, scrub inherited Git-root/object overrides. Missing objects become a scoped acquisition decision, not incidental production network during tests. Normal hooks and process-local commit identity only.
4. **One commit means intermediate HEAD remains baseline.** R1 preimages must be checked against actual prior-step worktree bytes/modes (or a correctly managed dedicated intermediate index), not `ls-tree HEAD`/index pretending to be e4. The three new paths must be absent from worktree and index. After all patches use tracked diff **plus untracked added paths**, not `git diff --name-only` alone, for the 32-path allow-list. Stage only that explicit set; read status/diff/log before normal commit. No reset/clean of existing user/old fixture work; initial checkout/reset into the new absent-created fixture is permissible, record it accurately.
5. **Runtime provisioning authorized, task-local.** Use new isolated tooling/cache/venv paths, fixed Core requirements (`jsonschema==4.23.0`, `pypdf==6.16.2`), CPython3.12.14 and previously recorded transitive pins/uv0.12.15 when available. If an exact historical pin is unavailable, preserve the failure and return a concrete alternative before declaring equivalence. 6. **Return recovered identity/equivalence and runtime/import outcomes before test execution.** The preflight's 4–6 tests are categories, not actual method names; they are not approved argv. Include a real Git-aware current-source check beyond a tree listing; avoid reproducing the old assembly suite for appearance. No new Freeze feature/test implementation.
7. **Durability: portable partial-repository snapshot preferred to a potentially hydrating bundle.** `git bundle --all` in a partial clone may traverse missing blobs or fail; do not run it blindly. Package a verified byte-copy of the acquired DB (including shallow/sparse/promisor metadata) and its materialized tracked/test-asset worktree into a self-contained compressed archive, after removing real remotes and checking config for credentials. No venv, Git credentials, untracked unrelated material or production archive. This is a backup of the **available partial DB**, not a complete repository/history. Store an explicit inventory of physical objects, missing reachable blobs/history and materialized bytes. Archive stays outside reconstruct until size measured; up to **50 MiB** may be preserved in the new packet with hashes and `-text` protection. Above that return for size/storage decision; manifest+recipe alone is not verified offline restoration.
8. **Restore test in a second new independent directory** by extracting that archive, verifying no external path links/hardlinks/alternates, inert origin, same HEAD/tree/parent/shallow boundary and available object/materialized-byte inventory. Verification is offline with no acquisition remote/lazy fetch. Runtime dependencies can use the separately pinned task-local venv, explicitly not bundled/offline-reinstallable unless separately proven. Archive creation must not mutate original candidate or lose evidence. Prefer one final snapshot after justified test assets are materialized so it reflects the actual verified fixture.
