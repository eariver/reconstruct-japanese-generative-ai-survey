# 会話を全部渡さずに覚える――Mem0の品質と処理負担をどう読むか

2025年4月28日にPrateek Chhikaraらが公開したMem0の論文は、長い会話から必要な情報を取り出して保持する方式を報告した。新しいメッセージ対を、会話の要約と直近の発言に照らして事実へ整理し、既存のメモリと比較して追加・更新・削除・変更なしを選ぶ。実験ではこの処理にGPT-4o-miniを使う。グラフを加えたMem0gは、人物などの実体と関係を保持し、関係が変わった履歴も扱う。[Mem0 §2](https://arxiv.org/html/2504.19413v1#S2)

評価対象はLOCOMOの10会話で、論文によれば1会話は平均約26,000トークン、質問は平均約200問である。単一の会話箇所から事実を探す質問、複数箇所を組み合わせる質問、時系列を問う質問、会話と一般知識を組み合わせる質問の四種類を扱う。答えのない問いを扱うadversarialの質問種別は除外されており、分からない時に答えを控えられるかは、この結果では確認できない。[Mem0 §3.1](https://arxiv.org/html/2504.19413v1#S3.SS1)

品質指標も読み分けが要る。F1とBLEU-1は主に参照回答との語の重なりを測る。次表のJは、別のLLMが質問・参照回答・生成回答を見て正誤を判定したスコアである。その判定用プロンプトは、参照回答と同じ話題や時点を含む回答を寛容に正解とするよう指示しているため、厳密な事実確認や人間による品質保証とは同じではない。著者は10回の評価の平均と標準偏差を報告するが、確認した本文と判定用プロンプトからはjudgeの正確なモデル版を確定できない。[Mem0 §3.2・Appendix A](https://arxiv.org/html/2504.19413v1#A1)

同じ論文内の比較では、全会話を渡す方式のJがMem0より高い一方、Mem0は回答時の入力量と遅延を小さくしている。p95は応答時間の95パーセンタイルを指す。次表は著者による測定であり、独立した実験再現の結果ではない。[Mem0 Table 2](https://arxiv.org/html/2504.19413v1#S4.T2)

| 同論文内の方式 | Overall J（%） | 検索＋回答生成のp95（秒） | 回答用コンテキストのトークン数 |
|---|---:|---:|---:|
| Mem0 | 66.88 ± 0.15 | 1.440 | 1,764 |
| Mem0g | 68.44 ± 0.17 | 2.590 | 3,616 |
| 全会話を渡す方式 | 72.90 ± 0.19 | 17.117 | 26,031 |

グラフ版はこの集計でMem0よりJが1.56ポイント高い一方、遅延とコンテキスト量も増える。しかも、同論文の単一箇所を問う質問と複数箇所を組み合わせる質問では、Mem0gのJがMem0を下回る。グラフを足せば多段推論が必ず良くなるという結果ではない。一般知識を組み合わせるopen-domainのJはZepが76.60、Mem0gが75.71、Mem0が72.93だった。[Mem0 Table 1](https://arxiv.org/html/2504.19413v1#S3.T1)

要旨にある「OpenAIに対して約26%改善」の比較相手も区別したい。これは著者がChatGPTから抽出したメモリを全て回答用コンテキストへ渡す手順で、そのJは52.90である。全会話を渡す比較相手や、ChatGPT製品全体の性能と混同できない。[Mem0 §3.3・Table 2](https://arxiv.org/html/2504.19413v1#S3.SS3)

先行するWujiang XuらのA-MEMは、メモリをキーワード・タグ・文脈説明付きのノートとして保持し、関連ノートとのリンク生成と既存ノートの更新を行う。こちらも外部メモリだが、同じLoCoMoという名前だけで論文間の数値を順位表にまとめることはできない。A-MEM v5はadversarialを含む五種類の質問をF1/BLEU-1などで評価し、GPT-4o-miniでは質問種別に応じて40または50件のメモリを検索する。両論文では会話長や質問数の説明も異なり、評価集合が完全に同じとは確認できていない。Mem0論文の既報A-Mem行と、著者がJを測るために再実行したA-Mem*行も別の結果である。[A-MEM §4・Appendix B.4](https://arxiv.org/html/2502.12110v5#S4)、[Mem0 Table 1](https://arxiv.org/html/2504.19413v1#S3.T1)

さらに、保存HTMLの表を照合すると、A-MEM v5のGPT-4o-mini行はmulti-hop F1が45.85、temporal F1が12.14なのに対し、Mem0論文の既報A-Mem行では、この二つの質問種別に対応する値が逆になっている。ここではどちらかを推測で訂正せず、質問種別を揃えた直接比較を保留する。再実行に使った版・検索設定・評価質問の対応確認が必要である。A-MEM自身も、メモリの組織化が基盤モデルの能力に左右され得ることと、現実装がテキスト中心であることを限界として記している。[A-MEM Table 1・§6](https://arxiv.org/html/2502.12110v5#S4.T1)、[Mem0 Table 1](https://arxiv.org/html/2504.19413v1#S3.T1)

導入判断では、回答の品質、回答時の入力量・遅延に加えて、メモリを作り、更新し、誤記や不要な情報を直し続ける負担を測る必要がある。Mem0には要約生成やLLMによる更新処理があり、論文には保存量・構築の観測もあるが、表のトークン数は全LLM処理の合計や総料金ではない。会話以外の手続き的推論やマルチモーダルへの拡張も今後の課題として残る。この研究が示すのは、特定の会話評価における有望な品質と回答時負担の組合せであり、すべての用途での優位や長期の運用費削減ではない。[Mem0 §2.1・§3.2・§4.5・§5](https://arxiv.org/html/2504.19413v1#S4.SS5)
