Root §11.3 text controls (decision lines 186–189; technical addendum §67; operator addendum §66):

- The **original historical package SHA remains original** in the result basis.
  `package.basis.state_sha256` is the historical value recorded at acceptance time. The leaf

  drift is tolerated IFF **all** of the following hold simultaneously, reimplemented path-based

  1. `sha256(package file bytes) == acceptance.package_sha256` (sibling acceptance binds exact

  2. `sha256(acceptance file bytes) == basis.<family>_acceptance_sha256` (basis pins exact
     acceptance; same-SHA different-path refused);
  3. **same canonical SOURCE path**: `package.basis.state_path` equals the canonical
     State path string derived from the accepted Profile `source_root` + config
     `state_authority.authoritative_filename` (same file identity the package was created

     to the fresh retained dest;
  4. same `issue_id` + same `research_profile`/`publication_profile` in package, acceptance,
     Profile, and basis;
  5. valid retained before-State/COPY chain exists (fresh `R/retained/before/...` COPY of the

### 1.3 Classification key (used in every §2 row)

- **RC (retained content)**: pure content predicate re-executed State-free in LEAF against basis-pinned bytes.
- **HI (exact historical identity)**: byte/path/digest/epoch identity checked by HISTORIAN
  (`verify_versioned_history`), never re-derived in leaf; leaf consumes basis-pinned refs only.
- **CN (current nonpublication authority)**: live-State/Profile/lifecycle/selection/tool predicate checked
  by HIGH `observe_renewal_authority` / `_observe_renewal_entry` outside proof; leaf drops it, keeps only
  file-label agreement from basis-pinned bytes where noted.
- **TC (old/current tool-contract)**: receipt closure, schema/style/recipe/prompt contract identity, executable
  evidence; HISTORIAN binds recorded epoch blobs; HIGH checks current closure/contract/HEAD; leaf checks only
  file-SHA equality of content contracts where they are content inputs (prompt/schema bytes), never tool-epoch
  validity.
- **DM (disallowed migration)**: any change to research acceptance, Profile, Architecture, Draft authority,
  pipeline/quality semantic contract, review requirements, route family, or build recipe specification that
  refuses and requires a separate migration contract (decision §2). U reuse mismatch, changed check-family,
  unsupported contract/recipe/schema are DM, not U exceptions.

Missing-API rule (per task): current missing APIs (fresh COPY verifier, renewal-aware P2V entry, U renderer
runner, C staged wiring) are planned new code, NOT automatic blockers. A blocker is ONLY an unresolvable
semantic: a predicate that cannot be made State-free without weakening it (hash-only acceptance, dropped
coverage, broad pending, caller verified dict). Those yield precise NO-GO (§9).
