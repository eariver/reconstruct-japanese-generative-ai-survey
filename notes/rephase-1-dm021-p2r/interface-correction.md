## C5 — error/classification consistency (feedback §5)

Single wrapping rule: never propagate bare `ProposalError`. Every P1 failure is caught and re-raised as `RetentionError` with `code="P1_REFUSED"`, `cause` = original exception (whose message already starts `ORIG_CODE: detail`), and detail embedding the original code:

```
RetentionError(code, phase, disposition, detail, owned=None, cause=None)
str(err) == f"{code}: [{phase}/{disposition}] {detail}"
```

- `code`: machine token (`P1_REFUSED`, `PATH_*`, `RETENTION_*`, `INCOMPLETE_RETENTION`, `INVALID_RETENTION`, `INDETERMINATE_INVOCATION`, …). `phase`: `PRE_P1_PIN|P1_CALL|POST_P1_SNAPSHOT|PREFLIGHT|CLAIM|WRITE|FINALIZE|MANIFEST_PUBLISH|VERIFY`. `disposition`: `REFUSED_PRE_WRITE` (no writes performed) | `OWNED_PARTIAL` (root claimed, partials preserved, retry refuses) | `INCOMPLETE` | `INVALID` | `INDETERMINATE_INVOCATION` | `VERIFIED` | `CAPTURED`. `owned`: `{retained_root: {dev,ino,mode}|None, owned_files: [{path,dev,ino,size}], observed_extra: [...]}` for actionable post-claim reports; pre-write refusals carry `owned=null`. Generic string-only reports are not used.
- No persistent close-fault flag in manifest/inventory. A close-failed manifest publish reports `INDETERMINATE_INVOCATION` from the **invocation** (even if complete bytes remain on disk; never rewritten into success). A later standalone `verify_retention` may return `RETAINED_SET_VERIFIED` for matching bytes without knowing the historical close failed — consistency, not historical success attestation. Never promise readback reconstructs an unsaved failure event. Initial `INDETERMINATE_CLOSE` code is withdrawn in favor of `INDETERMINATE_INVOCATION` (invocation disposition, not stored flag).

## C6 — ownership and I/O discipline (feedback §6)

- Safe reads use no-follow/nonblocking descriptor opens where feasible: `os.open(path, O_RDONLY|O_NOFOLLOW|O_NONBLOCK)` then `fstat` type check (regular only; FIFO/device/dir → fail without `read`), then `read`; ancestor walk uses `O_RDONLY|O_DIRECTORY|O_NOFOLLOW` fds with `fstat` identity. Type-swap between `lstat` and `open` thus fails closed (`PATH_ALIAS`/`PATH_NOT_REGULAR`) instead of opening a FIFO.
- Claimed root + files use dir-relative operations: hold `rootfd = os.open(<proposal_dir>/retained, O_RDONLY|O_DIRECTORY|O_NOFOLLOW)` after exclusive `os.mkdir`; record `fstat(rootfd)` identity `(st_dev,st_ino,st_mode)`. Every ancestor dir opened relative to parent fd (`os.open(part, O_RDONLY|O_DIRECTORY|O_NOFOLLOW, dir_fd=parentfd)`); every COPY/manifest created via `os.open(name, O_CREAT|O_EXCL|O_WRONLY|O_NOFOLLOW, 0o664, dir_fd=parentfd)`. Before/after each write/readback: `fstat` rootfd + parent fds + file fd compared to recorded identities; mismatch → stop, no foreign cleanup (`ROOT_IDENTITY_CHANGED`/`ANCESTOR_REPLACED`). Path-only `O_EXCL` plus post-write checks alone is withdrawn as insufficient; ancestor replacement cannot redirect a write because the write fd is bound to the pinned parent fd, not re-resolved path. No global-CAS/multi-file-atomicity claim.
- Every opened descriptor has explicit close disposition: normal `os.close(fd)` error → `CLOSE_FAILED` (or `MANIFEST_CLOSE_FAILED`); if a prior write/read error is already in flight and cleanup-close also fails, preserve the original error as `cause` and attach close error in `owned` (original error wins). Short writes: loop `os.write` until pinned length; positive short progress continues; zero-progress or `OSError` → `WRITE_FAILED` (distinct from `WRITE_SHORT` only in tests that inject a single short return to prove loop completion — implementation loops, tests distinguish loop-success vs zero-progress failure, not "any short write fails").
