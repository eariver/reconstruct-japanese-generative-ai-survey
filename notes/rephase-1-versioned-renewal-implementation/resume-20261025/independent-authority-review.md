## 2. BLOCKING F1 — Source reverify compares fresh-vs-fresh, not pinned-vs-fresh (TOCTOU pass)

**File:lines:** `scripts/survey_versioned_renewal_source_v2.py:248-288`, especially `:286-288`.

```python
seen: dict[str, str] = {}            # :248 — stores rel->label only, no bytes/SHA
def _check_ref(...):                 # :249-256 — reads via _fd_read, checks SHA, discards bytes
    ...
    seen[rel] = label                # :256 — label only
...
for rel, label in seen.items():      # :286
    if _fd_read(repo, rel, f"reverify {label}") != _fd_read(repo, rel, label):  # :287
        raise RenewalSourceError("BASIS_DIGEST_MISMATCH", f"pinned file changed during call: {rel}")  # :288
```

`seen` never stores pinned bytes or expected SHA. The final loop reads the same path **twice in immediate succession** and compares the two fresh reads. If evidence bytes change **between** `_check_ref` and the final loop, both final reads observe the **new** bytes, compare equal, and pass. The intended invariant — "live files must still equal basis refs" and "pinned file changed during call" — is not enforced.

Contrast the correct pattern in the same file: `_Session.reverify` (`:180-184`) correctly compares `fresh != self.pinned[rel]`.

**Exploit/control scenario:** Single-writer still allows a concurrent editor, flaky filesystem, or malicious supplied QA/review file swap to replace an accepted row (e.g., `accepted_refs` evidence-acceptance JSON) after `_check_ref` passes but before `load_renewal_accepted_authority` proceeds to content validation. Both final `_fd_read` calls see the swapped bytes, return equal, no refusal. Downstream content validators then run on attacker bytes while `validate_renewal_basis` reports `BASIS_VALID`. This breaks "beforeState COPY not live; exact closures; raw FD safe JSON on pinned bytes; IO swallow" and the Layer-A promise to "reverify pinned bytes after the call."

**Minimal contract-preserving repair (no contract change):** store pinned bytes/SHA in `seen` (e.g., `seen[rel] = (label, data, sha)` from `_check_ref`/`ret_data`), then final loop compares `fresh != pinned` or `sha(fresh) != expected_sha`. Keep error code `BASIS_DIGEST_MISMATCH` and fail-closed disposition. Do not weaken to fresh-vs-fresh equality or drop the reverify.
