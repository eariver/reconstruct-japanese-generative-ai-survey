# Astra scope selection — finish the contract without an opaque-source projection claim

2026-10-08. Analysis only, fixed409 unchanged. General's original analysis and correction remain preserved; neither is implementation authority. The correction still mixes “projected emitted reader values” with an opaque-source conservative bundle while promising no parser. Those are different designs.

## Decisions already made

1. **Do not implement a declared-bundle route as currently proposed.** Hash-binding more declared files is useful, but it does not itself compute their emitted values, identify every dependency or justify comment/layout equivalence. Current manifest/Gate already bind STYLE bytes; that is not a new repair. A blanket renderer-emitted-construct restriction without an explicit recognizer cannot establish runtime closure for arbitrary hand-authored TeX.
2. Preserve existing **DIRECT_PRIMARY/PRIMARY_ONLY** capability and its honest limits. No automatic rejection/migration of historical manual editions, no claim that this route now covers all supporting semantics. Do not add a new Gate scope that silently upgrades declared-file membership into complete publication acceptance.
3. **Prefer one coherent generated Longform reader-input/derivation increment**, rather than a new raw-bundle format now and an adapter later. Its finite trusted serializer, same-object output generation and exact replay can preserve semantic/mechanical separation without inverse-parsing arbitrary TeX. This is a justified investment direction, not a claim that it is cheap or already implemented. The complete field/authority feasibility table below is required before this contract unit closes.
4. Initial candidate support should be **THEMATIC + LONGFORM_SPECIAL** with an explicitly bounded existing longform document shape. Do not claim Retrospective viability merely from Profile enums or reuse Thematic labels/as-of assumptions for it. Preserve Retrospective's current direct-primary capability; complete generated Retrospective remains separate until its semantics are mapped.
5. No new reviewer role or fusion of authorities. Existing pre-TeX Reader-Surface semantic review judges the complete canonical reader input before source materialization. Later exact-manuscript/PDF SEMANTIC_EDITORIAL (including source fidelity and bibliography), VISUAL, Architecture and Human Preview remain. A free-text `longform_revision.review_reference` is not review authority and cannot synthesize PASS.

## Shape of the proposed coherent contract

- Use authored **structured Longform content**, not a projection guessed from arbitrary TeX. The reviewed object contains every emitted cover/frontmatter/as-of/title/heading/kicker/summary/package/narrative/timeline/technical-note/claim-boundary/cross-comparison/citation/bibliographic/style-visible value and order. Distinguish publication-authored revision prose from accepted Draft/result text; constrain cited source choices to accepted authority rather than falsely claiming all prose was mechanically copied from Draft.
- Only required reader identity/context/content enters semantic identity. Existing manifest accountability details, runner/review-reference/recorded-at/provenance/debug fields stay out unless actually rendered. Variable provenance comments should move to mechanical evidence rather than forcing semantic re-review. Internal identifiers used only as TeX labels must be safe tokens/hex, not arbitrary executable text or rendered “kickers” by accident.
- Renderer and bibliography/style materialization consume **that exact canonical reader object**; independent readback re-derives it from validated accepted + authoring inputs and compares all three outputs. Exact source/tool/style/control hashes and receipt provenance are mechanical, not substituted for semantic judgment. Code/style change with identical complete reader input requires renewed mechanical evidence, not automatic semantic re-judgment; existing exact PDF/visual/Human byte rules still apply.
- Support a known main/bib/style output set, fixed trusted serializer/style interface and explicit local inventory, analogous to B's bounded generated route. No arbitrary supporting `.tex`, dynamic include/filename/raw-TeX escape hatch or hidden source-emitting package. Unsupported shapes stop; installed TeX/build behavior and real rendered proof remain build/visual responsibilities, not a claimed universal dependency solver.
- New route/schema/receipt/producer/readback are real implementation costs and must be budgeted. No schema-free bundle fiction, no all-internal renderer arguments copied as “reader IR”, no Weekly field coercion or legacy-JSON fallback. Current Gate/manifest exact admission and selected State/provenance boundaries must remain.
- Initial supported operation is preparation/two-pass generation at configured **DRAFT_COMPLETE → stage:reader-publication-validation**, using a persisted review before TeX/Bib/style writes. Do not transplant the old revision wrapper's delete-before-validation behavior or silently widen the Weekly R1 refresh owner into Special. Pending-preview regeneration requires its own subsequent evidence/contract if not demonstrably supported by the selected operation.
