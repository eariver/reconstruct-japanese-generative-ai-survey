- **O-B1 — Basis/authority call sequencing and pin-recheck points are unnamed as an operator procedure.** §7 signature `observe_renewal_authority(root,state_path,basis_path)` cannot run "before capture" when the basis file does not yet exist (§5: basis written last), and §7 also requires calls "before capture, finalize and immediately before activation" plus rechecks after work. - **O-B3 — QA/review supply boundary and exclusive-inventory rule need exact operator text.** §§5–6 fix the model (supplied QA/review records at final repo-contained immutable paths, pinned not writer-owned, never self-generated PASS; U reuses OLD RECORD paths+SHAs, C mints new RECORDs; exclusive inventory covers declared evidence files inside R) but name no declaration procedure: how supplied paths are declared, reloaded, hash/size-checked, and listed in the exclusive inventory without sweeping arbitrary untracked files (cf. technical O4). - **O-B4 — Recovery operator next-actions need exact error/intent/CLI binding.** The §7 table states the right dispositions but leaves the executable contract to pre-code: exact typed errors and CLI exit codes per row (`TARGET_EXISTS`, `RECORD_COLLISION`/`INTENT_COLLISION`, `ALREADY_ACTIVE` readonly with existing-record path, `INDETERMINATE` preserve with observed old/new/unknown, close/fsync/replace/postread/foreign-inode primary+secondary reporting, never delete referenced records), resume-intent equality (which `renewal_id`/basis/proof/set/record fields must match for `resume_renewal_activation` to install vs refuse), and fresh-id retry for incomplete R (no same-byte takeover). - **O-B5 — Repeat and renewal→editorial chaining need exact chain mechanics.** §§7–8 require a second same-reader renewal only on another genuine eligible Core change with a fresh basis (retry of the exact active record is readonly `ALREADY_ACTIVE`), one mixed editorial/renewal chain (active-inclusive max32, strictly increasing sequence, nondecreasing time, no cycles; latest legacy before first versioned activation is the permanent anchor; repeated operations never roll it forward), and renewal→editorial via ordinary P1 repeated pre-Preview (`prior KEEP` + fresh State `COPY`, true-repeat P2V on the NEW pointer). Pre-code must show the chain walker accepts the renewal kind, `supersedes` edges for repeat renewal, anchor non-rollover across repeats, P1 repeated pre-Preview KEEP/COPY against the renewed before-context, and preserved P1 identical-reader refusal plus R1/canonical pre-write refusal in the new mode. Capability tests (repeat renewal, renewal→editorial, R1×2→editorial→renewal anchor, history/current readback, readonly already-active retry) are mandatory in the same unit — not claims about existing modules.
- **O-B6 — Semantic/staleness predicates beyond style bytes are the highest operator risk.** Byte equality (renderer-equality for U, trio/manuscript/PDF digest equality) does **not** prove semantic freshness. The decision contains the right gates (§2: research/Profile/Architecture/Draft/pipeline-quality semantic contract/review-requirements/route/recipe-spec changes refuse and require a separate migration; §4: preserve token safety, accepted-Draft restrictions, DID/card/primary/access mappings, directive refusal, full accepted-ref equality; §6: old manuscript must satisfy all current source/Architecture/fidelity requirements and the current fixed review/check contract must still accept the original scope; stale family forces U refusal or C), but fixes no finite predicate family or staleness procedure.
