Selection conditions: (a) legacy `legacy_revalidation` + editorial `editorial_activation` branches in `schemas/publication-surface-revalidation.schema.json` preserved VERBATIM (prove by `git diff <R3_head> <adapter_head> -- schemas/publication-surface-revalidation.schema.json` showing ONLY an added `oneOf` alternative + `$defs/renewal_activation`, zero hunks inside legacy/editorial branch bodies); (b) every other schema touched shows additive-only diff or no diff (no new required keys, no `additionalProperties` relaxation, no kind rename); (c) closure delta explicitly listed (if a new `survey_editorial_renewal_v2.py` joins the 50, the decision amends the fixed 50 with the exact name/path, never silent widening; file-pin-only vs imported edge classified per `169–195`); (d) code-commit-before-authority (meaningful source commit before any renewal receipt/seal); (e) A.2 historian is the ONLY old-identity bridge; CURRENT `validate_seal`/`verify_retention`/`verify_staged_source`/`validate_editorial_receipt` are NOT used as historians (A.0–A.2). Schema addition alone meeting (a)–(e) is sufficient to select the adapter; it is not grounds to demand a full migration contract or to deny bounded renewal.
- **Ordinary later implementation change (adapter installed):** tool-only `.py` changes with (a)–(c) unchanged (same schemas, same closure name set modulo reviewed expansion, same contract/route/recipe rules) renew via the INSTALLED adapter under A.2–A.3 without new branches. Any change tripping contract/closure/schema/route/research/DM022 predicates routes to a separate migration contract with its own fixture chain + independent review (predecessor §3.B triggers retained as B-triggers, not as automatic renewal refusal for the bootstrap itself).
- Predecessor "same-contract reviewed implementation-only change" (Alternative A) is therefore refined, not deleted: A holds for steady-state changes AFTER the bounded adapter is installed; the adapter install itself is the bounded renewal contract.

### A.5 File authority only; no cryptographic authenticity/approval beyond files

Historian + CURRENT validators together prove ONLY: exact paths exist as regular files (no-follow, bounded), bytes hash to recorded SHAs (+byte_count/page_count where declared), JSON parses strictly and validates against the stated CURRENT schemas, self-digests recompute, labels/profiles/route cross-equal, retained COPY mapping + inventories hold, tool-epoch blobs equal recorded T rows, externals equal recorded hash fields, chain links/anchor/sequence/depth/chronology hold. They do NOT prove: who authored a review, that a `PASSED`/`PASS` record reflects genuine human reasoning, that placeholder content is publication-worthy, or that any key signed anything. Semantic/visual QA PASS, Gate `PASSED`, Human Gate `APPROVED`, and Production NO-GO on placeholder editions remain operational judgments on file authority (R3 reader/visual inspection precedent); synthetic type-actor PASS is never genuine approval. No authority cache, no `verified-dict`, no retrospective genuine PASS conversion.
