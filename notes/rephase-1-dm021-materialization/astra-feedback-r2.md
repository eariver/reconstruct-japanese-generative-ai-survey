# Astra materialization correction review — remaining design gaps

2026-10-16 JST. Post-review staged TeX/Bib/style +manifest is a useful candidate direction, unlike reader-only staging. Initial/correction documents remain proposals. Before selection resolve these exact gaps in a separate addendum, without source/tests:

1. **State bytes unchanged != healthy State.** Correction156–181 again claims existing pending→revalidation bounds the install/adoption gap and review-path binding is the ONLY missing piece. Strict State validation checks checkpoint artifact bytes; replacing them invalidates old State even when State JSON bytes are untouched. Longform has no pending-basis readback entry. Withdraw that resolution: future editorial checked-context/public post-adoption readback, truthful reason/binding, ownership/failure window and unadopted Candidate collision remain design-open. No zero downstream changes/fully specified P4. Do not use existing Weekly fallback as editorial permission.
2. **Coexistence must be P2R+P2V, not public P1 success.** Correction58/81/199 says P1 remains bound after staging; public P1 remains destination-conflict after retention. Require that refusal plus P2R persistence and fresh P2V SCOPE_BOUND remain valid with complete staging outside retained/. New source files are not consumed by those observers.
3. **Artifact verifier needs exact historical namespace/dependencies.** `verify_staged_source(root,manifest)` + no Profile/State reads is insufficient to derive canonical proposal namespace safely. Prefer explicit supplied proposal path too, a required exact retention_manifest_ref in staged manifest, actual P2R retained validation, and historical retained State COPY→KEEP Profile layout (not mutable live State). Scope review must be type/path/digest/substantive-scope bound independently in readback, using exact historical metadata and existing scope checks without faking current authority. State/Profile historical parsing is not current-State admission. If existing helpers require an adapter, describe the narrow actual interface and budget; no unbound-self-manifest or implicit old P2V token.
4. **Replay code/tool policy must be explicit.** Re-rendering uses executing/current code; merely labelling recorded producer_HEAD informational does not make replay invariant to renderer/schema/style changes. Define the exact rendering+validation dependency set, require appropriate recorded/current byte equality or explicitly scope code-relative replay, and bind staged style to the actual pinned style input rather than to itself. No arbitrary historical code execution. Artifact-only HEAD must not invalidate unchanged replay dependencies, but unsupported tool/KEEP drift may refuse. “Verifies after live adoption” is conditional on preserved immutable refs/replay dependencies, not guaranteed for arbitrary future schemas/paths/code. Don't claim independent rederivation of accepted research from current State in an artifact-only verifier.
5. **Record-last and failure shape.** Single immutable STAGED_ONLY completion artifact, written last and closed/read back, not rewriting status to STAGED_INCOMPLETE after failure. Partial manifest is invalid; close-failed invocation can leave valid bytes which later verifier observes without attesting that invocation succeeded. Exact4file/ancestor closure, no aux/build outputs within owned namespace. Snapshot drift after self-readback must compare original expected bytes/input pins, not a fresh snapshot of changed outputs. Specify P2V re-observation after writes without comparing self-including full maps or legitimizing stale originals. No existing-root reuse/takeover by byte equality unless a separate justified contract is chosen.
6. **Build claim qualification.** The source may lack a standalone Python PDF-build API for this staged namespace, but the repository has build workflows/tooling; absence of a selected managed staged-build entry is not “no PDF build exists”. P3 can supply ordinary exact source inputs for inspection or a separate disposable build, without certifying that workflow integration, rendered QA, new Human Preview or Gate admission. Do not write build auxiliaries into the closed4-file materialization root.
